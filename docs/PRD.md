# PRD — My Tasks (할 일 관리 앱)

| 항목 | 내용 |
|------|------|
| 문서 종류 | 제품 요구사항 문서 (Product Requirements Document) |

## 1. 개요

My Tasks는 설치나 로그인 없이 브라우저에서 바로 쓰는 개인용 할 일 관리 앱이다.
서버 없이 HTML/CSS/JavaScript 세 파일로 동작하며, 모든 데이터는 사용자의 브라우저(localStorage)에 저장된다.

## 2. 목표와 비목표

### 목표

- 할 일을 빠르게 추가·완료·수정·삭제할 수 있다.
- 카테고리(업무/개인/공부)로 분류하고, 진행 상황을 한눈에 파악할 수 있다.
- 새로고침이나 브라우저 재시작 후에도 데이터와 설정이 유지된다.
- 키보드, 마우스, 터치, 스크린 리더 어느 쪽으로도 사용할 수 있다.
- 모바일과 데스크톱 화면 모두에서 쓸 수 있다.

### 비목표 (현재 범위 밖)

- 계정, 로그인, 기기 간 동기화
- 서버 저장 및 여러 사용자 간 공유·협업
- 마감일, 알림, 반복 일정
- 사용자 정의 카테고리 (카테고리는 3개로 고정)
- 하위 할 일, 첨부 파일

## 3. 대상 사용자

- 업무·개인·공부 할 일을 한곳에서 가볍게 관리하려는 개인 사용자
- 계정 생성 없이 로컬에서만 데이터를 보관하고 싶은 사용자

## 4. 기능 요구사항

### 4.1 할 일 기본 기능

| ID | 요구사항 |
|----|----------|
| F-01 | 입력창에 내용을 쓰고 Enter 키 또는 "추가" 버튼으로 할 일을 추가한다. |
| F-02 | 빈 내용(공백만 포함)은 추가되지 않으며, 입력창이 흔들려 알려 준다. |
| F-03 | 체크박스로 완료/미완료를 전환하고, 완료 항목은 취소선으로 표시한다. |
| F-04 | 각 항목의 ✕ 버튼으로 삭제한다. |
| F-05 | 할 일은 `{ id, text, completed, createdAt, category }` 구조로 저장한다. |
| F-06 | 각 항목에 생성 시간을 상대 시간("방금 전", "2시간 전", "3일 전")으로 표시한다. |
| F-07 | 할 일이 없으면 "할 일이 없습니다. 추가해보세요!"를 표시한다. 검색·필터 결과가 없을 때는 그에 맞는 문구를 표시한다. |

### 4.2 카테고리

| ID | 요구사항 |
|----|----------|
| F-10 | 카테고리는 업무(work, `#4A90E2`), 개인(personal, `#27AE60`), 공부(study, `#8E44AD`) 세 가지다. |
| F-11 | 추가 시 드롭다운에서 카테고리를 선택한다. 기본값은 "자동"이다. |
| F-12 | 각 항목에 카테고리 색상 태그를 표시한다. |
| F-13 | 상단 필터 버튼(전체/업무/개인/공부)으로 목록을 거르고, 선택된 버튼을 강조한다. |
| F-14 | **자동 분류**: 카테고리가 "자동"이면 할 일 내용의 키워드로 카테고리를 정한다. 일치하는 키워드가 가장 많은 카테고리를 고르고, 동점이면 업무 → 개인 → 공부 순, 일치가 없으면 "개인"으로 분류한다. |
| F-15 | 입력하는 동안 드롭다운에 분류 결과를 "자동: 업무" 형태로 미리 보여 준다. |
| F-16 | 자동 분류는 새 할 일 추가 시에만 적용한다 (기존 항목, 수정 중에는 적용하지 않음). |

### 4.3 인라인 수정

| ID | 요구사항 |
|----|----------|
| F-20 | 할 일 텍스트를 더블클릭하거나 ✎ 버튼을 누르면 편집 모드가 된다. |
| F-21 | 편집 모드에서 텍스트와 카테고리를 함께 바꿀 수 있다. |
| F-22 | Enter로 저장, Esc로 취소한다. 수정 영역 밖으로 포커스가 나가면 저장한다. |
| F-23 | 텍스트를 비운 채 저장하면 원래 텍스트를 유지한다. |

### 4.4 진행률 대시보드

| ID | 요구사항 |
|----|----------|
| F-30 | 전체 진행률을 "5/10 완료 (50%)" 형식과 프로그레스 바로 표시한다. |
| F-31 | 카테고리별 완료/전체 수와 미니 진행률 바를 표시한다. |
| F-32 | 오늘 추가한 할 일 개수를 표시한다. |
| F-33 | 남은(미완료) 할 일 개수를 제목 옆 배지로 표시한다. |
| F-34 | 완료율 구간에 따라 응원 메시지를 표시한다. |
| F-35 | 대시보드는 필터·검색과 무관하게 전체 할 일 기준이며, 변경 즉시 갱신된다. |
| F-36 | 페이지를 열 때마다 격언을 무작위로 하나 표시한다. |

### 4.5 검색과 정렬

| ID | 요구사항 |
|----|----------|
| F-40 | 검색창에 입력하면 할 일 내용 기준으로 실시간(디바운스 200ms)으로 거른다. 카테고리 필터와 함께 적용된다. |
| F-41 | 정렬 방식: 완료 상태순(기본, 미완료 → 완료), 생성일순(최신 먼저), 카테고리순, 수동 정렬. |
| F-42 | 순서 변경 핸들(≡)을 끌거나, 핸들에 포커스 후 ↑/↓ 키로 순서를 바꾼다. |
| F-43 | 수동 정렬이 아닌 상태에서 순서를 바꾸면, 현재 보이는 순서를 유지한 채 수동 정렬로 전환한다. |

### 4.6 삭제와 복구

| ID | 요구사항 |
|----|----------|
| F-50 | "완료된 항목 모두 삭제" 버튼은 확인 다이얼로그를 거친 뒤, 필터와 무관하게 완료된 항목 전체를 삭제한다. |
| F-51 | 삭제 직후 알림의 "실행 취소" 버튼 또는 Ctrl+Z로 가장 최근 삭제(단일/일괄)를 원래 위치로 복구한다. |
| F-52 | 같은 내용(대소문자·공백 무시)의 할 일이 이미 있으면 추가 전에 경고하고 확인을 받는다. |

### 4.7 데이터 내보내기/가져오기

| ID | 요구사항 |
|----|----------|
| F-60 | 현재 할 일을 JSON 파일(`my-tasks-YYYY-MM-DD.json`)로 내보낸다. |
| F-61 | JSON 파일을 선택해 가져온다. 가져온 데이터는 현재 목록을 **교체**한다. |
| F-62 | 현재 할 일이 있으면 가져오기 전에 "백업 후 가져오기 / 백업 없이 가져오기 / 취소"를 묻는다. |
| F-63 | 형식이 맞지 않는 항목은 제외·보정하고, 빈 파일·깨진 JSON·5MB 초과 파일은 안내와 함께 거부한다. |

### 4.8 테마

| ID | 요구사항 |
|----|----------|
| F-70 | 우측 상단 스위치로 다크/라이트 모드를 전환한다. |

### 4.9 키보드 단축키

## 5. 비기능 요구사항

| 구분 | 요구사항 |
|------|----------|
| 성능 | 100개 이상의 항목에서도 부드럽게 동작한다. 검색·저장은 디바운스하고, 목록은 바뀐 부분만 갱신한다. |
| 접근성 | 모든 조작 요소에 ARIA 레이블을 제공하고, 삭제·수정 후 포커스를 적절히 옮기며, 결과를 스크린 리더에 알린다. OS의 "동작 줄이기" 설정을 따른다. |
| 반응형 | 480px 이하 모바일 화면을 지원하고, 터치 기기에서 조작 영역을 44px 이상으로 한다. |
| 피드백 | 모든 인터랙션에 호버·누름 효과, 애니메이션, 토스트 알림 중 적절한 피드백을 제공한다. |
| 안정성 | 저장 실패(용량 초과, 저장소 차단)와 손상된 저장 데이터를 처리한다. |
| 한글 입력 | 한글 조합 중 Enter로 인한 중복 입력을 방지하고, 단축키는 한글 입력 상태에서도 동작한다. |

## 6. 화면 구성

### 6.1 기본 버전 (루트)

가운데 정렬된 최대 600px 카드 하나에 위에서 아래로 배치한다.

1. 제목 + 남은 개수 배지 + 테마 스위치
2. 오늘의 격언
3. 진행률 대시보드
4. 카테고리 필터 버튼
5. 검색창 + 정렬 선택
6. 카테고리 선택 + 입력창 + 추가 버튼
7. 할 일 목록 (또는 빈 상태 메시지)
8. 내보내기 / 가져오기 / 완료된 항목 모두 삭제
9. 단축키 안내 (모바일에서는 숨김)

### 6.2 데스크톱 버전 (`web_version/`)

- 960px 이상: 왼쪽 사이드바(1~4, 9)와 오른쪽 본문(5~8)의 2단 구성으로 화면 전체를 사용한다. 사이드바는 스크롤해도 화면에 고정된다.
- 960px 미만: 두 영역이 위아래로 쌓인다.
- 기능은 기본 버전과 동일하며 같은 저장 데이터를 공유한다.

## 7. 알려진 한계와 향후 과제

- 데스크톱 버전은 1920px 이상에서 목록 행이 지나치게 넓고, 사이드바 아래가 비며, 목록 밀도가 낮다 (개선 항목은 [TASK.md](./TASK.md) 참고).
- 가져오기는 병합이 아닌 교체만 지원한다.
- 복구(Undo)는 가장 최근 삭제 한 번만 가능하다.
- 자동 분류는 단순 키워드 포함 여부로 판단하므로 문맥을 이해하지 못한다.
- 데이터는 브라우저 한 곳에만 저장되므로, 브라우저 데이터를 지우면 사라진다 (내보내기로 백업 필요).
